# Background controls and KDE desktop widget

Approved scope: the user approved a resident background app/global shortcut and a KDE panel widget as the starting place. GNOME shell integration and arbitrary control of widgets in other applications are separate work. Recognition remains explicitly activated; this feature adds no wake phrase or idle microphone capture.

## Interaction and lifecycle

The native GTK app remains the sole owner of recognition, policy and portal grants. Add a session-only “Keep available when window closes” option (off on ordinary launch), plus explicit Quit. `gui --background` starts a held application with a hidden Practice window; this is the D-Bus activation entry used by the widget. Normal launch or Open controls presents the existing instance. Closing in background mode cancels recording, approvals/countdowns and spoken read-back, then hides; explicit Stop revokes grants and Quit cancels everything and exits. Reopening the window preserves the current controller and does not reconnect or replay work. No preference or autostart change is made implicitly.

A granted global Show controls shortcut brings the existing app forward. Existing global push-to-talk can capture while the window is hidden. A final review result makes the window visible and emits a generic review notification if necessary; microphone/model errors never expose transcripts in shell UI. Window focus rules continue to cancel locally owned capture. Widget capture is a distinct explicitly started capture source and can be stopped from the widget or global cancel; it retains the existing duration cap and confirmation policy.

## Narrow local control API

Use the current GApplication well-known session-bus name `io.github.wayland_voice_control`, object `/io/github/wayland_voice_control/Controls`, interface `io.github.wayland_voice_control.Controls1`. Export versioned, transcript-free status and fixed methods: GetStatus, Show, StartRecording, FinishRecording, Cancel, Stop, Quit. No text, key chords, file paths, confirmation or permission grants can be submitted over this interface. StartRecording must require saved Setup, Live mode, explicit microphone consent, an already prepared model, an already granted keyboard session and idle state. All methods run on the GTK main thread. Show can cold-start the app via an installed D-Bus activation file; cold starts always construct Practice first. Mutating methods never automatically switch to Live or ask for permission.

Status is an allowlist of booleans and enumerated strings: protocol version, Practice/Live, workflow state, microphone state, model readiness, can_start, pending_review, window visibility and background enabled. It excludes status/error strings, model paths, transcripts, drafts, command details and settings. A StatusChanged signal lets the widget update promptly. Session-bus clients already operating as the user are in the local desktop trust boundary; this is not authentication or isolation from malicious same-user applications.

Custom `--settings` instances must not redirect or mutate the default widget instance. Use a deterministic distinct application ID/object path for an explicitly supplied settings file. The widget controls only the default instance. Service registration and callbacks must be torn down at exit; adapter shutdown must remain idempotent.

## KDE widget

Ship an optional Plasma 6.7+ package using the installed `org.kde.plasma.workspace.dbus` QML API, native Plasma/Kirigami controls and no shell-command execution. Compact representation is a keyboard-operable microphone button with a clear accessible name and tooltip; expanded representation shows a fixed, transcript-free status, Open controls, Start recording / Finish and review, Cancel, Stop and Quit. Use native theme colors, wrapping labels, practical button targets and a scrollable expanded layout. In Practice or when not ready, show a concrete setup instruction and disable recording. Detect service disappearance, discard stale status and disable capture immediately. Activation and method failures show a fixed actionable error and never retry a mutation automatically. Keep at most one request per action in flight.

A local installer explicitly registers the service and Plasma package in the user data directory using the checkout venv executable; no root, login startup, changes to the user's panel or shell restart. Build the widget ZIP as an exportable artifact and include widget source/service template in Python distributions. Removal is documented. GNOME can use the background app, app-menu launcher and global shortcut; GNOME panel UI is not part of this package.

## Validation

TDD for lifecycle, safe IPC status, capture gating, shutdown, custom-settings isolation and CLI forwarding. Native GTK tests use fake audio/input in an isolated bus/display. Exercise actual Gio D-Bus methods and signals across a private connection. QML tests instantiate real expanded controls with a fake bridge and cover enabled states, capture/finish/cancel, errors and keyboard/accessible naming; separately load the real Plasma package and run the real bridge against the private GTK service. Capture screenshots at compact and normal dimensions and inspect them, including dark/light and enlarged text where supported. Run the existing full pure/GTK suite, protocol checks, Ruff, compileall and wheel/sdist checks. Never open the host microphone or send real input for automated widget verification. Document exact evidence and remaining GNOME/Orca/user testing limitations; make no broad disability-access claim.
