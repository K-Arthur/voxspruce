# Security policy

## Reporting a vulnerability

Please do **not** publish suspected vulnerabilities, proof-of-concept exploits, secrets, or private data in a public issue. Use GitHub's [private vulnerability reporting form](https://github.com/K-Arthur/voxspruce/security/advisories/new) (Security → Advisories → Report a vulnerability). Include the affected commit or version, an explanation of impact, and safe reproduction steps. Share only the minimum necessary information; avoid audio, transcripts, and identifying data.

The maintainer will review reports as capacity permits. Do not assume a guaranteed response time or fix deadline. Please allow time for investigation and coordinated disclosure; do not access other people's systems or data while testing.

## Scope and support

The current development branch is experimental, and there is no published stable release or guaranteed support window. Reports affecting the current source and its privacy, capture, permissions, or input behavior are welcome. Third-party dependencies and speech models have their own maintainers and licenses; report upstream issues to their maintainers where appropriate.

For the design and known boundaries, see [security design](docs/security.md), [privacy](docs/privacy.md), and [release readiness](docs/release-readiness.md). Ordinary bugs and usability feedback belong in [issues](https://github.com/K-Arthur/voxspruce/issues).
